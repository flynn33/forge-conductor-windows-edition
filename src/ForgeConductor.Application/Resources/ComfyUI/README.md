# ComfyUI starter workflows

`starter_manifest.json` identifies an SD1 image workflow and Wan 2.2 5B workflows for text to video and image to video. Each entry has separate executable API graphs for a preview and a proposed final render. These files are starting graphs; the model must discover the current provider's node contracts and installed models before adapting them to the operator's request.

The node input names and output ports were recorded from the installed ComfyUI 0.16.3 source. The Wan graph also follows the installed `comfyui_workflow_templates_media_video` 0.3.56 `video_wan2_2_5B_ti2v.json` template. Its `Wan22ImageToVideoLatent` accepts an optional `start_image`: the text workflow omits it, and the image workflow connects `LoadImage` output 0. API graphs are constructed from these named contracts rather than translating frontend widget array positions.

The Wan preview uses 640 by 384 pixels, 81 frames at 16 frames per second, and 12 sampling steps. This is a 5.0625-second motion preview. The proposed final uses the official template dimensions of 1280 by 704 pixels, 121 frames at 24 frames per second, and 20 sampling steps. The dimensions are multiples of 32, and both frame counts follow the installed node's temporal stride of four with an offset of one. Both graphs explicitly request the installed core `SaveVideo` MP4 container and H.264 codec. The final settings require measured resource feasibility and may need revision with another preview and approval.

The video graphs reuse the host's existing `wan2.2_ti2v_5B_fp16.safetensors`, `umt5_xxl_fp16.safetensors`, and `wan2.2_vae.safetensors`. The official template's FP8 text encoder is not required by these graphs. The image graph initially selects the observed SD1 checkpoint `cyberrealistic_final.safetensors`. Its publisher is not identified by this resource, so it must be reused from an authenticated inventory or replaced by a separately identified installed SD1 checkpoint. Do not invent a download source. Publisher repositories recorded for the Wan models are discovery sources; preparation must resolve a pinned revision and exact SHA-256 before downloading and must seal the chosen installed identities.

For image to video, `example.png` is a typed `LoadImage.image` starting value. Bind the operator's authorized local image through the managed input upload and seal it before preview submission. Prompt, negative prompt, seed, dimensions, frame count, frame rate, and steps have named typed bindings in the manifest. Changing the final graph, any input, a creative parameter, or a dependency after preview requires another approval.

Use `comfy_validate` for preflight and `comfy_prepare` for the identified dependencies. Execute these through `comfy_run` with saved preview and final graphs and the manifest's expected output node. The managed path publishes the preview and waits for a later saved native user reply of `approved`, `yes`, or `render final`. A model argument is not approval. Final delivery requires verified output coverage and media inspection.

The native starter tests verify graph topology, port compatibility, required inputs, known choices, model bindings, approximately five-second motion, and typed parameter serialization against recorded contracts. This qualification does not imply that inference ran on this host or that the operator accepted the visual quality. Those qualification flags remain separate in the manifest and live generation receipts.
