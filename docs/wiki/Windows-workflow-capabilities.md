# Windows workflow capabilities in 1.3.14

Forge adds dedicated web search/fetch/HTTP, native DOCX/XLSX/PPTX creation, visible desktop/accessibility/browser/input/capture, native PNG drawing and image previews, independent model workers and persistent model-task schedules. These join the existing tools, specialists, read-only reviewers, evidence, process jobs, memory, policy and continuity.

Explicit HTTP supports GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS, with bodies for POST/PUT/PATCH/DELETE. Only GET/HEAD follow redirects; use mutating methods within the user's authorized task and inspect the observed response. Remote accounts and credentials must come from an authorized existing connection or explicit API input.

The owner selects host filesystem access for ordinary available local volumes or workspace mode for registered/configured roots. Relative artifacts keep the selected project's directory. Native ACL, namespace, reparse and authority checks remain; a model tool does not grant new filesystem mode or administrator rights.

Host-mode continuity recovery retains the registered project's canonical directory and identity. Native Read authorization applies to both the registered alias and recovered candidate, followed by a canonical subtree check; the broader volume capability does not replace the project directory. Unregistered/sibling canonical paths and revoked access remain denied. Focused recovery tests passed; current installed/native-chat qualification remains tied to its actual execution.

Office writers validate structured input and complete ZIP/XML packages before authorized atomic publication. They require no Office installation or Python runtime. Numeric/text spreadsheet cells retain their declared type; leading `=` text remains literal. Nonzero subnormal numeric values outside Excel's supported range are rejected; use literal strings to retain their text. Native PNG drawing produces diagrams/chart primitives. Generative artwork and cloud email/calendar/chat accounts need separately configured providers or authorized APIs.

Managed worker/reviewer Responses outputs add PNG image content alongside text metadata while preserving the original function-call identity. Ordinary text output retains its existing string form; image output uses `input_text` and `input_image` in the same `function_call_output`, with a 512 KiB encoded PNG preview bound. MIME/base64 errors are explicit. Fresh native and owned loopback-provider image-content checks passed; configured provider/model vision support still determines interpretation, and current installed Qwen qualification remains pending.

`agent_spawn` accepts `task` and `authorization`, with optional `agent_id` specialist playbook and `timeout_sec`. Independent model workers inherit the caller's mutable filesystem scope and a frozen permitted tool list, use fresh provider history, and retain separate receipts. Their closed spawn schema does not accept `read_only_tools` or `allowed_tools`; use the preserved read-only reviewer tools for independent review. Scheduled tasks separately support read-only mode and an explicit allowlist. Workers cannot spawn recursively, create schedules or approve policy gates. Poll actual output/state and confirm terminal cancellation. Existing specialist sessions remain distinct.

Worker scope also excludes legacy `session_checkpoint` and `session_handoff`, which mutate session continuity state. Their existing authorized Primary/Fallback routes remain available; this restriction applies to independent and scheduled workers.

Up to sixteen independent workers can run simultaneously, including scheduled inference. Finished terminal threads release admission capacity when another run starts or status is read. Worker receipts remain sealed and addressable by run ID beyond the reviewer's sixteen-record lifetime limit. Raw output remains bounded to 256 KiB, with serialized receipt files bounded to 4 MiB. Recurring runs do not automatically delete earlier outputs; retained files require disk space, and storage errors remain explicit.

Schedules require explicit owner/task authorization context and a running Manager. UTC times or intervals of at least 60 seconds persist in separately authorized storage. Future triggers restore after restart; live runs do not overlap; uncertain interrupted effects block automatic replay until an explicitly authorized new attempt. Schedule state is distinct from the latest worker's actual result. Authorization references are audit context, not identity proof, and no outbound email is sent.

`schedule_list` with `{}` and create/cancel/run-now receipts return bounded summaries. Full task text, frozen scope, retained output/history/logs and notification receipts remain available through `schedule_list` with `schedule_id`. Concatenate `record_json_page` strings in offset order, then parse the complete JSON. Continue with `next_offset` and the returned canonical decimal `revision`; `max_bytes` accepts 1–32,768 bytes and defaults to 32,768. Nonzero offsets require the revision guard, and a changed record returns `conflict` requiring a restart at offset 0. Pages respect UTF-8 character boundaries, and cross-owner reads remain denied. The service bounds each response to 128 KiB before MCP framing.

An unsaved notification receipt remains visible as actual summary submission/error metadata, with `revision: null` and `record_paging_available: false`. Full-record reads return `conflict` until a successful store commit, so an unsaved continuation token cannot be reused for different data after restart.

Meaningful changes use the installed Forge Conductor application's local Windows toast channel. Inspect the actual bounded `last_notification` receipt/error: Windows accepting a submission leaves `display_confirmed: false`. Existing notification settings can block submission, and the notifier does not change them. Model output and remote content are omitted; notification failure does not change or replay the model task.

Desktop input reports submission and requires subsequent observation. Browser launch is not proof of page loading. Screen capture includes overlapping visible windows, and Windows account/integrity restrictions still apply.
