The current 1.3.29 catalog contains 125 Primary/Fallback tools: all previous 112 plus eleven general ComfyUI tools and desktop scroll/drag. Native CMake/CTest jobs, paged accessibility reads, bounded previews, web, DOCX/XLSX/PPTX, desktop/browser input, PNG drawing/image analysis, independent workers and schedules remain. General ComfyUI automation adds managed local image/video workflows, dependency preparation, preview approval and verified artifacts alongside the separate legacy image provider. See [ComfyUI Automation](ComfyUI-Automation), [1.3.29 release notes](Release-1.3.29) and [versioned verification](https://github.com/flynn33/forge-conductor-windows-edition/blob/main/docs/validation/RELEASE-1.3.29.md). Historical measurements retain their original identities.

Rig's corrected display shows the observed native conversation and the Manager's enabled/disabled project/provider preference, distinguishing a read from a save. Inspect `visible_chat_continuity` in Primary MCP's `get_forge_status` for actual rollover state; preference readback does not establish completed rollover. The historical 1.3.19 package included this correction; its installed/readback and current-chat evidence remains bound to that artifact above.

Explicit HTTP supports GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS, with bodies for POST/PUT/PATCH/DELETE. Only GET/HEAD follow redirects; use mutating methods within the user's authorized task and inspect the observed response. Remote accounts and credentials must come from an authorized existing connection or explicit API input.

The owner selects host filesystem access for ordinary available local volumes or workspace mode for registered/configured roots. Relative artifacts keep the selected project's directory. Native ACL, namespace, reparse and authority checks remain; a model tool does not grant new filesystem mode or administrator rights.

Host-mode continuity recovery retains the registered project's canonical directory and identity. Native Read authorization applies to both the registered alias and recovered candidate, followed by a canonical subtree check; the broader volume capability does not replace the project directory. Unregistered/sibling canonical paths and revoked access remain denied. Historical recovery tests retain their original identity. The historical published 1.3.21 implementation clears a native read-pipeline error only after the complete read succeeds and preserves unrelated handoff/workspace errors. The exact 1.3.21 source suite and measured installed/native-chat checks passed for that historical artifact; see its verification record.

Office writers validate structured input and complete ZIP/XML packages before authorized atomic publication. They require no Office installation or Python runtime. Numeric/text spreadsheet cells retain their declared type; leading `=` text remains literal. Nonzero subnormal numeric values outside Excel's supported range are rejected; use literal strings to retain their text. Native PNG drawing produces diagrams/chart primitives. Filled rectangles now use exact requested pixel width/height, including one-pixel shapes and canvas clipping; the earlier NULL-pen drawing reduced dimensions by one. Ellipse behavior remains. The historical 1.3.21 clean-source suite passed the native desktop/image regression target, including exact-size rectangle and bounded-preview checks. Generative artwork and cloud email/calendar/chat accounts need separately configured providers or authorized APIs.

The optional ComfyUI `sd1` provider is disabled by default and requires an owner-configured loopback endpoint plus an existing compatible checkpoint. `image_provider_status` reads current configuration and core-node/checkpoint inventory; inventory availability does not establish a loaded model or image quality. The six routes are `image_edit`, `image_generate`, `image_job_cancel`, `image_job_resume`, `image_job_status` and `image_provider_status`. `image_generate` and `image_edit` return durable jobs. Poll `image_job_status` for actual state, error and publication measurements. `image_job_cancel` suppresses local publication; running remote work may continue. `image_job_resume` requires fresh current authorization and retrieves the existing exact prompt/workflow without a new generation or upload POST. Read-only status cannot resume or publish. Red mask 0 preserves exact original RGBA, red 255 selects generated pixels and intermediate values blend all four channels. Destinations and source/mask snapshots use fresh authority, sealed preconditions and atomic publication. Atomic publication is not a distributed compare-and-swap against external writers. An isolated direct-native ComfyUI smoke run passed six cases, including generation, unmasked editing, exact masked RGBA preservation, observed running cancellation and explicit recovery after a controlled lost acknowledgement. The helper deliberately withheld an observed matching HTTP 200; it did not exercise a real network outage. These checks used private fixture-issued scopes and do not qualify integrated Manager IPC, LM Studio/Qwen delivery, semantic instruction following or model quality. See [local image-provider guide](https://github.com/flynn33/forge-conductor-windows-edition/blob/main/docs/IMAGE-PROVIDER.md).

Managed worker/reviewer Responses outputs include native PNG image content in the original function-call output, with a 512 KiB base64-encoded preview bound. The stock LM Studio 0.4.25 MCP result stores a saved image filename/Markdown reference; preview display alone did not establish model pixel input in the current chat. `image_analyze` validates an authorized image and starts an independent read-only run using the working Responses path. Supply an explicit authorization and optional question, then poll `reviewer_status` for actual output, errors, token usage and evidence integrity/seal. The source is read when the provider invokes `image_read`; admission does not freeze its bytes. The analysis uses the existing project-authorized read-only reviewer catalog, has no executor history, cannot approve gates and cannot be started recursively by independent workers.

`image_read`, `image_write`, `desktop_capture` and `image_analyze` accept optional `preview_max_dimension` 128–2,048, default 256. The preview's longest dimension respects that request without enlarging a smaller source; adaptive resizing retains the 512 KiB base64 limit. Inspect actual `preview_width`/`preview_height`, `preview_max_dimension_requested`, `preview_encoded_bytes`, `preview_encoded_byte_limit` and `preview_reduced_for_byte_limit`. The full written/captured image keeps its dimensions, and invalid preview values are rejected before write/capture effects. Analysis forwards the option through admission and the fresh reviewer's requested image read. Higher resolution does not guarantee OCR or change the stock LM Studio metadata boundary.

`desktop_read` accepts zero-based `offset` (default 0) and `limit` 1–300 (default 100 scanned positions). Follow `next_offset` while `has_more`; receipts retain observed row `index`, scanned/returned/total counts and `truncated`. Native pages respect 32 KiB aggregate text and 64 KiB encoded JSON before MCP framing, so a page can be shorter than requested. Indices belong to each newly observed tree and may change with the UI; restart observation when it changes. Password text remains excluded, and reads do not activate the window or submit input.

`cmake_test_run` uses an explicit initialized build tree with enabled shell policy and current Read/Write/Execute authority. Default mode tests the existing tree; explicit `build_and_test` builds an optional target before testing, with separate configuration/filter values and one shared 1–3,600-second timeout (default 1,800). CTest starts only after confirmed uninterrupted build success. `cmake_test_status` exposes actual nullable phase outcomes and validated JUnit counts; outer `ok` means retrieval. Counts come from consistent testcase records, and failure pages do not invent expected/actual values. UTF-8 rows use zero-based `failure_offset`, `max_failures` 1–32 and a 24 KiB encoded row-list bound. Reports are limited to 8 MiB and 100,000 cases; path, length and SHA-256 checks preserve integrity without authenticating producer data. An unreadable/unsealable report is marked `report_unverified` with null counts/hash, while unfinalized host-crash outcomes remain unknown and are not replayed. Existing log/wait/kill tools use the job ID. The tools do not configure implicitly or add clangd. See [CMake/CTest source guide](https://github.com/flynn33/forge-conductor-windows-edition/blob/main/docs/CMAKE-CTEST.md).

`agent_spawn` accepts `task` and `authorization`, with optional `agent_id` specialist playbook and `timeout_sec`. Independent model workers inherit the caller's mutable filesystem scope and a frozen permitted tool list, use fresh provider history, and retain separate receipts. Their closed spawn schema does not accept `read_only_tools` or `allowed_tools`; use the preserved read-only reviewer tools for independent review. Scheduled tasks separately support read-only mode and an explicit allowlist. Workers cannot spawn recursively, create schedules or approve policy gates. Poll actual output/state and confirm terminal cancellation. Existing specialist sessions remain distinct.

Worker scope also excludes legacy `session_checkpoint` and `session_handoff`, which mutate session continuity state. Their existing authorized Primary/Fallback routes remain available; this restriction applies to independent and scheduled workers.

Up to sixteen independent workers can run simultaneously, including scheduled inference. Read-only reviewers have a separate sixteen-concurrent-run limit. Finished terminal threads release admission capacity when another run starts or status is read. Worker and reviewer receipts remain sealed and addressable by run ID; the unpublished 1.3.15 candidate removed the earlier reviewer sixteen-record lifetime limit, retained in 1.3.19. Terminal reviewer status reloads the durable receipt and reports actual evidence integrity and SHA-256. Raw output remains bounded to 256 KiB, with serialized receipt files bounded to 4 MiB. Recurring runs do not automatically delete earlier outputs; retained files require disk space, and storage errors remain explicit.

Schedules require explicit owner/task authorization context and a running Manager. UTC times or intervals of at least 60 seconds persist in separately authorized storage. Future triggers restore after restart; live runs do not overlap; uncertain interrupted effects block automatic replay until an explicitly authorized new attempt. Schedule state is distinct from the latest worker's actual result. Authorization references are audit context, not identity proof, and no outbound email is sent.

`schedule_list` with `{}` and create/cancel/run-now receipts return bounded summaries. Full task text, frozen scope, retained output/history/logs and notification receipts remain available through `schedule_list` with `schedule_id`. Concatenate `record_json_page` strings in offset order, then parse the complete JSON. Continue with `next_offset` and the returned canonical decimal `revision`; `max_bytes` accepts 1–32,768 bytes and defaults to 32,768. Nonzero offsets require the revision guard, and a changed record returns `conflict` requiring a restart at offset 0. Pages respect UTF-8 character boundaries, and cross-owner reads remain denied. The service bounds each response to 128 KiB before MCP framing.

An unsaved notification receipt remains visible as actual summary submission/error metadata, with `revision: null` and `record_paging_available: false`. Full-record reads return `conflict` until a successful store commit, so an unsaved continuation token cannot be reused for different data after restart.

Meaningful changes use the installed Forge Conductor application's local Windows toast channel. Inspect the actual bounded `last_notification` receipt/error: Windows accepting a submission leaves `display_confirmed: false`. Existing notification settings can block submission, and the notifier does not change them. Model output and remote content are omitted; notification failure does not change or replay the model task.

Desktop input reports submission and requires subsequent observation. Browser launch is not proof of page loading. Screen capture includes overlapping visible windows, and Windows account/integrity restrictions still apply.
