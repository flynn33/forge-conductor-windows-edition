# Manager

The Manager owns the existing per-user project, tool, memory, policy, settings, deployment, telemetry, and persistence services. WinUI sends typed commands through ManagerConnection and ManagerRequestDispatcher rather than editing databases or LM Studio configuration itself.

Sessions are LM Studio chats. The historical Managed Run/readback UI remains removed. The primary stdio MCP composition owns native chat Auto Continuity; the 1.3.21 checkpoint and reconciliation contract is described below. The 1.3.21 source retains independent Manager-owned model workers and persistent schedules through dedicated MCP routes, with fresh histories and separate receipts. Native CMake/CTest jobs use the existing Manager-backed shell-job owner when available; standalone ownership remains explicit. Source, package, installed-tool and live-model qualification are pending. See [1.3.21 implementation notes](Release-1.3.21).

## Product actions

Workspace selects/registers projects, manages ordered packages, and binds a selected policy repository directly from the folder picker. Settings retains Load effective settings, Save and read back, Revert pending edits, Test LM Studio, and Restart Manager. Saved record actions remain selection plus buttons; the old scope-maintenance scheme is removed.

Rig's Runtime configuration card exposes Ensure manager, Restart service and Stop service through the existing handlers. Wait for owned work to finish or confirm terminal cancellation before restarting/stopping Manager. Scheduled triggers need Manager to remain running. The controls remain in the current App source; final 1.3.21 installed UI acceptance is pending its separate executed record.

Independent worker scopes exclude legacy `session_checkpoint` and `session_handoff` continuity mutations while retaining their authorized Primary/Fallback tools. Managed worker/reviewer Responses outputs add bounded PNG image content with text metadata and original call identity; text-only outputs keep their existing form. Historical native/loopback-provider exclusion and image cases passed. The historical disposable-profile schedule lifecycle and reconnect probe also passed. The installed 1.3.19 [qualification](Release-1.3.19) records the exact four-payload package checks, nine actual native-chat cases, and Qwen recognizing three private image properties through a fresh independent read-only `image_analyze` run and sealed `reviewer_status` output. Stock preview delivery alone does not establish pixel interpretation. The inner provider image request was not captured, and a new live rollover was not tested.

Native CMake/CTest jobs retain one shared build/test/report deadline, project-owned durable typed receipts and actual phase outcomes. Status separates retrieval from success, retains observed interrupted phase results and leaves unavailable counts or unfinalized crash phase results null. It does not replay uncertain effects. Existing named logs, bounded waits and kill/cancellation use the returned job ID. Report seals detect later changes without authenticating producer data or approving gates. See [CMake/CTest source guide](https://github.com/flynn33/forge-conductor-windows-edition/blob/main/docs/CMAKE-CTEST.md).

The 1.3.21 continuity implementation clears a read-pipeline diagnostic only after the full native conversation read succeeds, while retaining unrelated handoff/workspace errors. It also adds an atomic DPAPI-protected visible-handoff checkpoint and one OS-held writer lease per routed home. Observer reconstruction requires fresh project/provider/route authority and exact native request, successor or packet-recovery evidence. Send and New chat receipts are stored before dispatch; uncertain effects are not replayed. Invalid or incomplete reconciliation exposes `recovery_pending` while retaining the packet. These changes remain pending final reconstruction qualification.

Install or repair remains one action for Primary, Fallback, and CLU, preserving foreign registrations and unknown fields. Existing provider configuration and telemetry remain. No credential or login step is added.

Historical Auto Continuity was verified with a reserve-triggered pause, not physical context exhaustion. Rollover was verified while the primary MCP worker stayed alive. Interrupted handoff after idle-process eviction is not durable and is not claimed.

Retained backend run/session records are compatibility history, not a replacement product run manager or a claim of native-chat recovery. See [Process Model](Process-Model) and [Continuity](Continuity).

The current `agent_spawn/poll/cancel` and `schedule_create/list/cancel/run_now` services preserve frozen/current-policy scope, actual state/output/cancellation and explicit uncertain-effect records. Manager must remain running for schedule triggers. Shutdown stops the schedule loop and cancels its actual workers before shutting down worker transport/storage. Local Windows notifications persist submission acceptance/error with display unconfirmed; they do not send outbound messages or change Windows notification settings. See [Windows Workflow Capabilities](Windows-workflow-capabilities).
