# Local-model workflow repair record, 1.3.13

The October 6 report identified seven failures in the 1.3.12 runtime installed as MSIX 1.3.12.1. Investigation read the original persisted reviewer receipts and the native transport, authority resolver, Manager route, filesystem directory helpers, and shell supervisor. Product version 1.3.13 and MSIX 1.3.13.0 carry the repairs described in the [release notes](../releases/1.3.13.md).

## Reproduced mechanisms

- The persisted reviewer failure interval was approximately 120.509 seconds with `deadline_exceeded`, WinHTTP 12002, zero observed tokens, and no provider response. `LMStudioResponsesTransport::perform` used a fixed 120-second receive timeout. Per-run timeout propagation now spans the request, service tool loop, transport, Manager codec, and verified reviewer receipt. A delayed loopback response also showed synchronous `WinHttpSendRequest` returning after approximately 2.508 seconds despite queried one-second receive/header options, followed by an immediate receive result. The transport now submits asynchronous WinHTTP requests with owned callback state, headers, body, and read buffer retained through `HANDLE_CLOSING`; API calls and closing serialize on the same handle. A synchronous wrapper waits for each completion. The request guard uses a monotonic receive budget from submission through body completion, clipped to the operation deadline; it closes the exact owned request when the budget expires and rejects late success. Admission rechecks prevent shutdown/cancellation from missing a request before registry insertion. The bounded provider-cancel POST bypasses its own remembered local cancellation while preserving caller deadline/cancellation and shutdown checks.
- `McpExecutionContextResolver::resolve` narrowed recovered authority to the selected project root on every call, discarding active evidence roots. `WindowsProjectWorkspaceAuthority::bindConfiguredRoot` correctly refused that narrower capability. Explicit activation now resolves the owning capability, and subsequent recovery retains the current issuer's explicitly bound roots without restoring removed grants.
- `McpToolPackAdapter` forwarded process launch and tracked-shell work to the Manager before local cwd validation, whereas synchronous shell validated locally. All three routes now perform the same local check before execution or dispatch. Brokered reviewer opening-file paths also authorize locally before dispatch, so the Manager cannot broaden a connector’s active roots.
- A native ACL regression reproduced root-file success followed by nested creation failing with the exact Win32 error 5. `NativeFileOperations::ensureAuthorizedParentDirectories` and child creation requested unnecessary directory `FILE_DELETE_CHILD` access. The repair removes unrelated access requests and retains strict sharing/reparse controls. A separate real existing-file ACL denial covers the atomic-write adapter: native Win32 5/1314 becomes `filesystem_access_denied` with the operation and canonical target, while shared storage and authority-policy errors keep their contracts.
- `WindowsShellService::validateCommandEnvelope` enforced 4,096 bytes, and normalization placed the complete script in argv. The existing supervisor already owned bounded stdin delivery, EOF, cancellation, and process-tree lifetime. The 65,536-byte route uses that existing mechanism with a fixed UTF-8 loader and preserves the original `-Command` final-statement failure status. Direct PowerShell comparisons identified that using stale `$LASTEXITCODE` changed a final cmdlet failure after a native failure; the loader’s guard preserves the original exit 1 for failed final statements and explicit exit values.

## Verification scope

`scripts/test.ps1 -Configuration Release -Architecture x64 -Parallel 4` rebuilt the complete configured graph and passed **156/156 CTest entries** in **49.13 seconds**, exit code 0. The three static gates (native stack, no Python, no attribution) and the production package-persistence contract also passed. Actual loopback tests enforce a one-second Responses deadline, a six-second override, a 50 ms caller deadline, partial-body deadlines/cancellation, shutdown, and a separate outgoing provider-cancel POST. The timeout is per provider Responses request; model-discovery GET and remote-cancel requests retain their separate bounds. A review's total lifetime and admitting MCP request are separate from this budget.

An isolated real CLI/Manager authority probe passed 56 MCP calls covering explicit/recovered bindings, connector reconnection, nested Unicode writes, 65,536/65,537-byte command boundaries, and all three cwd routes both within and outside active roots. It verified the owner's configuration bytes remained unchanged. Direct PowerShell comparisons matched the original command exit behavior in 38 cases across PowerShell 7 and Windows PowerShell 5.1.

Final clean-source product build, signature, installed payload, integration activation, and provider qualifications are recorded with executable hashes in the release's `release-verification.json`, `release-provenance.json`, and `distribution.json` assets.
