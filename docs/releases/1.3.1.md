# Forge Conductor 1.3.1 release notes

Version 1.3.1 completes full project-memory browsing and direct record maintenance in the native Windows application.

## Highlights

- **Display All** loads every active record for the selected project through stable 100-record Manager pages.
- Paging rejects duplicate records, repeated or missing cursors, count drift, project-identity drift, and nonterminating results.
- **Settings → Data maintenance** shows project-memory records in a scrollable extended-selection list.
- Every memory row has a visible **Delete record** control. **Delete selected** supports normal Windows multi-selection, confirms once, calls `project_memory.forget` for each selected key, and refreshes the remaining rows.
- Continuity reset remains a separately labeled wipe action. The existing exact-confirmation scope reset remains available separately.
- Native MCP hosts prefer PowerShell 7 and make Git, PowerShell, Windows system tools, `PATHEXT`, and `COMSPEC` available to authorized child processes even under a minimal launcher environment.

## Compatibility

The stable package identity remains `ForgeConductor.Windows`; the package version advances to `1.3.1.0`. Existing projects, memory, instruction packages, governance state, run history, continuity records, and LM Studio registrations remain in the ordinary per-user profile.

The release does not change the meaning of a record or introduce a new maintenance subsystem. Record deletion uses the existing `project_memory.forget` API. Continuity and full-scope resets continue through the existing Manager maintenance API.

## Verification

The Release build passes all 153 configured tests. Focused integration coverage creates 101 project-memory records and verifies that Display All retrieves the complete ordered result across multiple Manager pages. Native-tool tests verify the explicit child environment and PowerShell/Git paths. Both static gates and the attribution gate pass.

The GitHub release contains a source-bound, development-signed Windows 11 x64 MSIX and distribution bundle. The publisher certificate must be trusted explicitly on first installation. Installed UI interaction remains an operator acceptance step.

Live supported-provider successor creation, restore, acknowledgement, and fencing were not rerun. Enabled automatic continuity therefore remains `Preparing`, not `Active`.
