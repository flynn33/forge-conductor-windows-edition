# Forge Conductor 1.3.6 release notes

Version 1.3.6 repairs periodic view movement introduced when the Actions frame was removed in 1.3.5. The native app design, telemetry cadence, existing controls, and three LM Studio integrations remain.

## Exact change

`MainWindow.xaml` restores `Visibility="Collapsed"` on the diagnostic `ManagerState` TextBlock. `MainWindow::RunAction` changes the generic connecting-status branch from `else` to `else if (action != Action::Refresh)` so background polls do not replace diagnostic text with command-progress text.

These are the two behavioral lines in source commit `9912541debc92c1117cceab0f6322c4e62728ee4`. Previously the shared layout contained a visible status row alternating between one-line connecting text and a multiline telemetry result. Its changing height moved the Rig panel on each refresh. Collapsing that diagnostic row removes its layout allocation; excluding Refresh from the progress-text branch leaves the background refresh behavior intact.

## Geometry and telemetry verification

The check used the real WinUI XAML inside an in-process observer with an injected isolated `ManagerConnection`. It sampled geometry every 20 ms while the existing 500 ms telemetry timer completed 16 polls with a 150 ms injected telemetry response. This is actual WinUI layout measurement with controlled data, not inspection of the installed window.

The baseline Rig position varied from 343.333 to 474.000 logical units: a 130.667-unit range and 25 position transitions. The fixed variant remained at 308.667 logical units with zero transitions across the same 16 polls. `ManagerState` was Collapsed with zero height throughout the fixed measurements. Injected CPU values continued changing from 30.0% through 34.0% in both variants; refresh was not disabled to obtain stable layout.

- Complete x64 Release CTest matrix: `100% tests passed out of 153`; `Total Test time (real) = 32.36 sec`; exit code 0.
- Release App build, backend build, and package construction exited 0.
- All three static gates passed.
- Before the final documentation commit, the local repair candidate was installed as `ForgeConductor.Windows_1.3.6.0_x64__wj2yg5ac9gadp`. App and Manager were running from that package; installed App, Manager, and CLI hashes matched that candidate payload, and the App reported a responding window.

The publication package is rebuilt from the final release commit. The earlier candidate identity check does not establish that the installed binaries match that final rebuild.

Native-control initialization failed with `MODULE_NOT_FOUND` for `kernel.js`. No installed-window visual inspection is claimed. Process/window presence and matching binary hashes establish installed identity, not a visual acceptance pass.

## Retained continuity bounds

The 1.3.5 native predecessor/successor evidence remains historical evidence for that release; this telemetry repair does not expand its continuity guarantee.

Auto Continuity was verified with a reserve-triggered pause, not physical context exhaustion. Rollover was verified while the primary MCP worker stayed alive. Interrupted handoff after idle-process eviction is not durable and is not claimed.
