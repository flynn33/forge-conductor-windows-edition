# 1.3.9: MCP project bootstrap and continuity recovery

The installed 1.3.8 executable reported no instruction package for the Forge project even though its durable store contained a version-1 manifest and 28 pinned instruction records. The MCP path read only version-2 queue rows; conversion occurred only when Manager listed the queue. Manager and MCP now share conversion, with bounded reads/writes, stable identities, explicit missing-file coverage, and durable empty-queue suppression.

The older failed session also submitted eight empty `fs_edit` calls. The advertised schema had no parameters despite the implementation requiring `path`, `old`, and `new`. Those parameters are now advertised, together with usable `fs_glob` and `fs_move` schemas. Existing filesystem authorization and mutation behavior is retained.

Budget checkpoints now retain the authorized workspace and recently observed file paths. Default `context_get` selects the current client's or project's packet and accepts historical fallback only when its workspace matches. Pathless and unrelated historical packets remain explicitly retrievable by ID; their missing task details cannot be reconstructed. Automatic persistence preserves an explicitly recovered packet without inheriting another client's global packet.

LM Studio install/repair carries the selected registered project's ID and canonical folder to Primary, Fallback, and CLU. Inspection detects project drift. Packages and CLU policy remain project-scoped; a policy saved for another project is not automatically adopted.

Native specialist start/status now require a resolved project in their authorization capabilities. Previously the MCP router left the project absent because the catalog marked both actions as unscoped, while the session service correctly required a project-bound status capability. The repair retains strict ownership and project checks. The deployment verifier also uses the exact reviewed fingerprint of the repaired filesystem schemas.

The live desktop selected YWE (`2f9a1172-3309-4efb-a94a-ed2f56575438`, `D:\GitHub\YWE`) while LM Studio still launched the Forge repository. The saved YWE package and policy were present and readable. YWE implicit startup also rejected a historical repository identity mismatch; explicit registered-project startup passed without rewriting that identity.

Prepare now reuses a uniquely registered workspace only after exact alias matching and native Read authorization of its canonical root. It reads the existing project state and retains its integrity checks. New folders still use initialization, including its repository identity conflict guard; ambiguous aliases, child folders, and unauthorized roots cannot reuse a project.

## Practical limits
