# Forge Conductor 1.3.11: workspace bootstrap and complete native tool delivery

This is the public repair release following 1.3.6. It includes the instruction-queue and policy-source improvements developed locally as 1.3.7 and 1.3.8, the [bootstrap and continuity repairs](1.3.9.md), the [complete native delivery repair](1.3.10.md), and the Windows authorization correction below. The intermediate versions were local development builds, not GitHub releases.

## Repairs and impact

The desktop selected YWE while the three LM Studio registrations launched the Forge repository. The active package and policy belonged to the selected project. App, Manager and deployment now carry the selected registered project ID and workspace into Primary, Fallback and CLU, and verification detects project drift. Stores remain project-specific; no policy is copied between projects. Existing registered workspace reuse performs native Read authorization, exact unique alias matching and project-store integrity checks.

Legacy package conversion previously occurred in Manager listing while MCP bootstrap read only the new queue format. Both paths now share bounded migration, retaining pinned content, repeated ordering, explicit queue removal and visible missing-content coverage. The queue can be removed, reordered and re-added directly. Policy selection supports a folder or a single file and rechecks the selected project after the picker returns.

`fs_edit` previously advertised no arguments although its handler required `path`, `old` and `new`. Its schema now exposes those fields; glob/move arguments and specialist start/status project requirements also match their handlers and service ownership. Implicit continuity recovery uses the current client/project, excludes unrelated or pathless fallback packets, and retains authorized workspace/recent-file evidence at a budget checkpoint. Explicit historical lookup remains available; missing task history is not invented.

Native LM Studio acceptance exposed a 50,000-character text-block limit. Policy inventories now use complete snapshot-validated pages and accurate bounded UTF-8 text offsets. Other large results use complete ordered fragments, without repeating the underlying operation. Strict reconstruction, catalog checks, scope checks and the whole-response limit remain enforced.

Native 1.3.10 acceptance rejected legitimate `shell_exec` cwd `D:/GitHub/YWE` with `invalid_request`. The same call failed in the actual-process regression against preserved 1.3.10. `WindowsWorkspaceAuthority::resolveRequestedPath` now normalizes supported request separators before the existing strict resolver. Configured roots, access, scope, traversal, namespace, reparse and deletion protections remain enforced. Filesystem and shell requests with native, forward and mixed separators are covered.

## Verification limits

The accepted 1.3.11 installation did not exercise a new reserve-triggered native rollover, physical context exhaustion, worker-crash recovery or every GUI action. Interrupted native handoff after idle-worker eviction remains the documented in-process limitation. The saved policy's 42 coverage gaps remain visible. No claim is made that every possible future failure is eliminated. The new publication build is qualified separately and is not installed during publication.
