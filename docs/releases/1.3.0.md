# Forge Conductor 1.3.0

Version 1.3.0 makes Workspace the direct operating center for Forge Conductor.

## Highlights

- The normal shell has four destinations: Workspace, Rig, Activity, and Settings.
- Projects can queue multiple instruction-package folders in a persistent order.
- Package intake is content-universal: every entry is inventoried and hashed without extension, encoding, size, count, depth, or name admission filters.
- CLU now performs development-policy governance only. It reports policy coverage, findings, notifications, corrections, and a redacted history.
- Automatic continuity is an independent per-project/provider preference.

## Compatibility

Legacy active instruction-package state is migrated into the queue. Existing governance state is read through the current schema migration. Project memory, managed-run history, continuity records, and unrelated LM Studio registrations are preserved.

The dedicated CLU role now exposes `clu.evaluate`, `clu.export_log`, `clu.findings`, `clu.resolve`, and `project_policy.read`. Clients depending on the retired `clu_*` continuity-control names must use the existing `continuity.*` runtime tools or Manager-owned automatic continuity as appropriate.
