# Forge Conductor 1.3.2 release notes

Version 1.3.2 prevents LM Studio's outer MCP deadline from ending valid long-running Forge tool calls before Forge can return their bounded result.

## Highlights

- Primary, Fallback, and CLU registrations now carry an exact integer `timeout: 180000`.
- The same value is emitted and validated in every synchronized plugin bridge and host-activation acknowledgment.
- Missing, stale, floating-point, string, null, or boolean timeout values are treated as configuration drift and repaired through the normal three-plugin deployment path.
- Foreign MCP registrations and unknown configuration fields remain unchanged.
- Validation gates no longer flag their own tracked policy files or depend on checkout line endings.

## Compatibility

The stable package identity remains `ForgeConductor.Windows`; the package version advances to `1.3.2.0`. Existing projects, memory, instruction packages, governance state, run history, continuity records, LM Studio registrations, and foreign MCP entries remain in the ordinary per-user profile.

After upgrading, finish or stop active MCP calls and use **Settings → LM Studio plugins → Install or repair all three plugins**. LM Studio reloads MCP configuration during repair. Then choose **Open LM Studio and connect plugins** and select the intended integration in the chat.

Fallback is an independent selectable integration and health role. A timeout does not automatically replay a call through Fallback or switch the chat back to Primary. Inspect the affected state before retrying a timed-out mutating call because its outcome can be ambiguous.

## Verification

The complete Release build passes all 153 configured tests and the static release gates. Focused coverage verifies generation, drift detection, deployed bridge status, and activation acknowledgment for exact signed and unsigned integer timeout values while rejecting missing, stale, floating-point, string, null, and boolean values.

A live Windows LM Studio `shell_exec` call requested a 90-second limit, ran for 70,312 milliseconds, and returned successfully after 70,545 milliseconds of tool status time. This host observation proves the repaired outer deadline exceeds the former 60-second cutoff; it is not a general performance guarantee.

The GitHub release contains a source-bound, development-signed Windows 11 x64 MSIX and distribution bundle. The publisher certificate must be trusted explicitly on first installation. Installed UI interaction remains an operator acceptance step.

Live supported-provider successor creation, restore, acknowledgement, and fencing were not rerun. Enabled automatic continuity therefore remains `Preparing`, not `Active`.
