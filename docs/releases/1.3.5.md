# Forge Conductor 1.3.5 candidate notes

Version 1.3.5 is a source candidate that corrects loaded-model discovery and addresses Manager-owned run/continuity contract gaps. Its planned uninstalled MSIX will preserve the stable package identity `ForgeConductor.Windows` with package version `1.3.5.0`; package construction and verification remain pending until the committed release pipeline emits its distribution receipt.

## Functional corrections

- Work Space discovery and Responses-session bootstrap now read LM Studio's native `GET /api/v1/models` inventory.
- Only valid `loaded_instances` IDs on `type: llm` entries are eligible. Downloaded-but-unloaded models, embedding models, malformed identifiers, and duplicates are excluded.
- Work Space **Test model discovery** uses the same loaded-instance contract. The separate Responses probe remains the productive provider-contract check.
- The durable agent-session goal limit is 128 KiB, matching the bounded managed-run instruction envelope so activated instruction-package content can reach session startup. An interpreted entry that cannot fit beside a task now fails explicitly without starting a run or advancing its queue cursor. Successful admission persists the exact cursor plan with a dispatch-pending run; multi-row advances are transactional, and provider/tool work starts only after the plan commits or restart replay reconciles an already committed plan.
- Managed-run start idempotency persists the effective `automaticContinuity` value and an identity for the original pre-enrichment request. Exact replay returns the originally admitted assignment even after package cursors, policy guidance, or continuity preference changes; a changed original request still conflicts.
- Saving the automatic-continuity preference updates the existing project/provider record with optimistic version checking. False-to-true-to-false changes keep one durable record, saving the already-effective value performs no timestamp-only rewrite, and restart readback returns the saved value. Protocol-v1 managed-run responses retain their established 19-field shape; the decoder also accepts the optional transitional continuity field.
- Repeated automatic rollovers in one run receive unique sequenced continuity operation and handoff identities. A later pre-successor checkpoint refresh compares the exact prior digest, preventing a stale retry from replacing newer completed work. Successor prompts repeat a UTF-8-safe bounded original task and the latest completed native-tool work, while unconsumed checkpoint states are durably abandoned when their owning run terminates or rollover fails. After the Manager acquires its process-wide instance lease, a pre-ingress recovery pass abandons checkpoint-only orphans from an earlier process; periodic maintenance leaves live checkpoints stable and resumes only records with durable successor intent.
- Manager, CLI/MCP, policy import, Doctor, native-shell execution, and LM Studio serve verification share one resolver that uses Windows, installed-tool, and machine-level search paths only. Caller `PATH`, `PATHEXT`, and `COMSPEC` values are replaced, and HKCU `PATH` entries and per-user command shims cannot participate in product command resolution. HKLM strings are read raw with no-expand semantics, so caller-controlled environment variables cannot rewrite machine configuration; only absolute, existing, non-reparse machine directories enter the search path.

The same-host LM Studio connection remains unauthenticated. Keep **Require Authentication** disabled (`json.tokenMode=disabled`). This candidate adds no token persistence, bearer-auth configuration, permissions UX, or authentication setup path.

## Evidence

- A native loopback regression proves discovery and Test reject a downloaded-only LLM and a loaded embedding, deduplicate a repeated instance, return the loaded instance rather than its different catalog key, and accept an inventory larger than 64 KiB within the 2 MiB bound.
- Native resolver regression and the static six-consumer audit prove that ambient executable shims are ignored by Manager, CLI/MCP, policy import, Doctor, native-shell execution, and LM Studio serve verification. They also prove HKLM values are read without caller-environment expansion, caller toolchain variables are replaced, and the explicit child `PATH` contains the required system toolchain while excluding per-user Forge, LM Studio, and dotnet tool directories.
- Durable managed-run and continuity regressions prove exact replay across mutable package/preference state, dispatch-pending cursor-plan recovery before provider effects, atomic queue-cursor updates, UTF-8-safe successor context, terminal checkpoint abandonment, lease-owned pre-ingress orphan cleanup, periodic live-checkpoint preservation, exact checkpoint replay, latest-work bootstrap/resume, and stale/post-successor refresh rejection.
- Manager regressions prove one project/provider preference record survives false-to-true-to-false changes and restart readback without duplicate or no-op writes. Protocol codec coverage proves the v1 encoder emits exactly 19 managed-run fields and the decoder accepts both the established and transitional shapes.
- The real-Manager memory regression proves 101-record **Display All** paging, one direct record deletion, and multi-record deletion through authoritative `project_memory.forget` readback.
- A live same-host check discovered and tested `openai/gpt-oss-20b` and completed the Responses contract probe without provider authentication.
- A fresh post-fix disposable Manager-owned continuity run passed with loaded model `openai/gpt-oss-20b`. It activated an instruction package, forced a context rollover, and proved successor create/bootstrap, structured acknowledgement, predecessor fencing, and productive work derived from predecessor native-tool output. The result reported one operation and one handoff.

Project-memory Browse/Display All and automatic continuity are distinct. The memory checks prove record paging and deletion. Separate fresh live provider and disposable managed-run successor checks passed on the Release x64 source build; neither proves packaged WinUI or installed acceptance.

## Candidate boundary

No 1.3.5 MSIX is claimed by this source note until the committed release pipeline emits and verifies it. Packaged WinUI interaction, taskbar launch, upgrade behavior, and operator acceptance remain pending. The planned validation package will be development-signed; production signing and publication remain owner actions.

The [`v1.3.4` GitHub release](https://github.com/flynn33/forge-conductor-windows-edition/releases/tag/v1.3.4) remains the latest published package. Historical release notes are unchanged.
