# Forge Conductor 1.3.3 release notes

Version 1.3.3 makes the active LM Studio workspace binding explicit and machine-readable.

- MCP initialization instructions name the authorized project folder, ordered instruction-package folders, and active development-policy source and revision.
- `forge_status` exposes the same facts under `workspace`, `instruction_packages`, and `development_policy`.
- Instruction packages carry an explicit read-in-order requirement, and an active development policy carries an explicit read-and-follow requirement plus `project_policy.read` locator.
- Forge `home` is labeled as application data only and cannot be mistaken for the project folder.
- Empty handoff paths and continuity implicit roots do not suppress the independently registered MCP project root.
- The LM Studio deployment verifier rejects missing, malformed, or incomplete initialization context.

The stable package identity remains `ForgeConductor.Windows`; the package version advances to `1.3.3.0`. During live qualification, the fail-closed database check quarantined the ordinary profile's `store.sqlite`, WAL, and shared-memory files after a failed migrated-database quick-check. The three files were restored byte-for-byte to `C:\Users\james\AppData\Local\Forge Conductor`, while the complete quarantine snapshot and the pre-restore WAL/shared-memory copies were retained. The LM Studio disclosure check used the separate `Forge Conductor 1.3.3 Live` profile.
