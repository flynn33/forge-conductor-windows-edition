# User guide

## Optional image generation and editing

Choose tools by purpose. image_write draws shapes and text. image_analyze starts an independent read-only interpretation of an existing image, and reviewer_status reads that analysis. To generate through the separately configured ComfyUI provider, first inspect image_provider_status, then start image_generate or image_edit and poll image_job_status. Use image_job_cancel for local publication suppression and image_job_resume for explicit fresh authorized reattachment to an exact existing provider job. Analysis and reviewer status do not start or report generative jobs.

The initial sd1 profile is disabled by default and requires an explicit owner-configured loopback endpoint and compatible checkpoint. Status reports unavailable or incompatible providers; Forge does not start a server or install a model. Inputs require explicit seed, absolute authorized paths and bounded dimensions. Mask red 0 preserves original RGBA exactly. Lost acknowledgements remain unknown without generation replay; status cannot publish recovered work. Cancellation may leave remote inference running. See [provider setup, examples and exact bounds](IMAGE-PROVIDER.md).

The isolated direct-native six-case ComfyUI smoke passed with 128/256-pixel outputs and 2/4/6 steps, including exact 8,192-pixel outside-mask preservation and controlled response-loss recovery. Integrated 1.3.27 Manager IPC/LM Studio qualification, semantic instruction following and full host model quality remain pending or unverified.


Launch Forge Conductor from Start. The destinations are **Workspace**, **Rig**, **Continuity**, **Activity**, and **Settings**. Work happens in LM Studio chats.

## Prepare a workspace

1. Register or select the project folder in Workspace and choose its provider profile.
2. Add instruction-package folders. Move queue rows up or down, or drag them, to define execution order. Remove any row whenever it is no longer needed, including an active row.
3. Under CLU governance, choose **Choose policy folder...** for a repository or **Choose policy file...** for one document. With a project selected, the chosen source binds immediately. You can browse before selecting a project; select a project and choose its policy again to activate governance.
4. Set **Auto Continuity** for the selected project/provider and review readiness.
5. Use the loaded model in LM Studio with the existing Forge integrations.

The Manager persists project access, packages, policy bindings, memory, preferences, telemetry and scheduled model tasks. The 1.3.27 candidate places the native chat observer under Manager lifetime, with Primary supplying authorized observations. Closing Forge's window does not cancel LM Studio chat work. Scheduled inference requires Manager to remain running.

The current 1.3.27 source catalog defines 112 Primary/Fallback tools, retaining the dedicated web, Office, desktop/browser, image, independent-worker and scheduled-task workflows and adding native CMake/CTest jobs. Integrated 1.3.27 build, complete tests, signed-package, installed-catalog and native LM Studio qualification are pending; isolated provider checks do not qualify these binaries. Call `host_capabilities` before assuming a capability is missing; see the [host capability guide](HOST-CAPABILITIES.md) for contracts and bounds. The owner can choose host filesystem mode for ordinary local volumes or retain workspace-only mode. Relative artifact paths keep the selected project directory in both modes.

Call `schedule_list` with `{}` for this caller/project's schedule summaries. Creation, cancellation and run-now receipts also return summaries. For complete task text, frozen roots/tool names, history, logs and notification receipts, call `schedule_list` with `schedule_id`. Append `record_json_page` from each response in order, then parse the complete JSON. Continue with `next_offset` and the returned `revision`; `max_bytes` is optional and accepts 1–32,768 bytes. A `conflict` means the record changed during the read: restart at offset 0. Inspect the reconstructed latest run's actual state/output before treating work as completed.

Native PNG previews can accompany tool results in managed worker/reviewer Responses content, with their text metadata and original function-call identity retained. Ordinary text results keep their existing output form; previews are limited to 512 KiB of encoded image data. Historical image-content checks and the installed 1.3.19 [qualification](validation/HOST-CAPABILITIES-1.3.19.md) record their own results: loopback-provider checks passed, and Qwen correctly recognized three private image properties through a fresh independent read-only `image_analyze` run and its sealed `reviewer_status` output. These results do not qualify 1.3.21. Stock tool-preview delivery alone does not establish pixel interpretation. The inner provider image request was not captured, and a new live rollover was not tested. Independent workers cannot invoke legacy `session_checkpoint` or `session_handoff`; those existing tools remain available through authorized Primary/Fallback calls.

For image detail, `image_read`, `image_write`, `desktop_capture` and `image_analyze` accept optional `preview_max_dimension` from 128 through 2,048 (default 256). Adaptive resizing retains the 512 KiB base64-encoded PNG preview limit and never enlarges a smaller source; full written/captured images keep their dimensions. Inspect actual `preview_width`/`preview_height`, requested-limit, encoded-byte and `preview_reduced_for_byte_limit` metadata. The image-analysis route forwards the same option to its admission read and fresh reviewer opening; poll `reviewer_status` for the actual asynchronous result. Invalid values are rejected before image-write/capture effects. Higher resolution does not guarantee exact OCR or resolve the stock LM Studio tool-result image metadata boundary.

To check exact source pixels, call `image_read` with `"samples": [{"x": 0, "y": 0}, {"x": 10, "y": 20}]` using coordinates within your image. Up to 64 points return measured `[R,G,B,A]` channels in request order. Inspect `decoded_rgba8_sha256` for the canonical frame-0 RGBA8 buffer and `preview_png_sha256` for the emitted preview bytes. Source, decoded-buffer and preview hashes measure different representations. Native channel measurements include source alpha; the existing preview remains opaque. This check does not prove what image input LM Studio sends to its stock chat model.

`image_write` rectangle fills now use the requested exact pixel width/height and clip at canvas edges. Earlier `NULL_PEN` rectangle rendering reduced each dimension by one pixel; the new 1.3.21 contract makes a requested 1×1 rectangle visible. Ellipse behavior is retained. The complete clean-source suite passed the native desktop/image regression target, including exact-size rectangle and bounded-preview checks.

For accessibility reads, call `desktop_list` first to obtain the exact visible window/PID. `desktop_read` accepts zero-based `offset` (default 0) and `limit` 1–300 (default 100 scanned positions). Follow `next_offset` while `has_more`, inspecting returned row `index` values and `scanned_elements`/`returned_elements`/`total_elements`. Each native page is bounded to 32 KiB of aggregate text and 64 KiB of encoded JSON before MCP framing; budget limits can shorten a page. Indices belong to each freshly observed tree, so refresh observation if the UI changes. The read does not activate the window or send input, and excludes password text.

## Instruction packages and status

A package is a folder. Intake inventories entries and streams hashes without extension, encoding, file-count, file-size, aggregate-size, depth, or name-based admission filters. Files, directories, reparse points, and read failures remain explicit. Safe derived text is bounded and content pages retain revision identity.

Queue removal and reordering take effect immediately and persist across refresh and restart. Removing a package deletes its queue binding; its source folder remains available and can be added again with the same revision. A model that has already read a package retains that text in its existing chat history.

The model can call `get_forge_status` to obtain `workspace.project_id`, `workspace.project_root`, binding-source fields, `instruction_packages.packages` in execution order, the development-policy source/revision, tool names/count, and agent count. `home` is application data, not the project folder. An empty continuity path does not erase the registered workspace binding.

Call `instruction_package.read` with the selected `queue_row_id` from status. Read all cursor pages; an incomplete text entry is continued with its `path` and `next_offset`. The response includes the selected package, returned entries and content, completion markers, and `next_cursor`. Opaque or inaccessible entries retain coverage information. Packages from another project are not substituted.

## CLU policy repository

CLU evaluates development-policy evidence. It does not create chats or control continuity. Use the folder picker for a repository or the file picker for a single policy document. A file source imports only that file, leaving sibling files outside its coverage. With a project selected, either source binds on selection.

The remaining controls are **Reload policies from source**, **Inspect status**, **Inspect findings**, **Export CLU log**, **Policy documents**, **Read document**, **Next part**, and **Selected policy document**. Reload intentionally adopts changed content from the bound folder or file. The model receives the bound source and the instruction to read and follow it through `project_policy.read`.

After a non-CLU tool operation, the adapter evaluates structured evidence and adds pending findings to the returned `clu_governance_notifications`. The loaded model therefore receives correction guidance. **Inspect findings** displays the findings and open count; Activity retains correlated evidence and correction history. Missing policy is an inactive state; findings remain nonblocking governance evidence.

The CLU role exposes `clu.evaluate`, `clu.export_log`, `clu.findings`, `clu.resolve`, and `project_policy.read`.

## LM Studio integrations

**Install or repair all three plugins** is one action for `forge-conductor`, `forge-conductor-fallback`, and `forge-conductor-clu`. Foreign integrations and unknown configuration fields are preserved. Each Forge registration uses the exact 180-second outer request deadline; Forge `shell_exec` remains capped at 120 seconds.

Primary owns automatic chat rollover. Fallback is an independent general-catalog integration, not automatic replay of an ambiguous timed-out mutation. CLU supplies governance tools and receives project packet context through shared initialization; recover packets through Primary or Fallback. No continuity plugin or new Forge credential is required. Same-host model traffic retains the existing unauthenticated loopback contract.

The 1.3.21 source retains the visible handoff phase across observer reconstruction in an atomic checkpoint protected for your Windows account. Recovery requires the current authorized project, matching provider and integration routes, and exact native evidence of the recorded request or successor. `get_forge_status` can report `recovery_pending` with the reason and recorded chat/packet IDs. Select the recorded chat to reconcile its evidence; the saved checkpoint alone cannot authorize a new project or repeat an uncertain Send or New chat. The retained packet remains available through authorized `context_get`. The 118-group Infrastructure suite passed, including the private same-PID observer reconstruction regression and 20 durability cases. Installed observer/UI interruption or connector rollover recovery remains unverified; physical context exhaustion and already-running agent reattachment were not exercised. Historical 1.3.20 checkpoint-process primitive evidence retains its original source identity and is not a current installed qualification.

## Process jobs, evidence, and reviewer tools

Use `shell_exec` for a foreground command of at most 120 seconds. `shell_exec` and `shell_job_start` accept up to 65,536 UTF-8 command bytes, including multiline scripts and here-strings. Forge delivers the script through supervised UTF-8 stdin with fixed launch arguments, so the Windows command-line length does not constrain that script. Pass the task's real `cwd`; Forge constructs explicit profile/account/toolchain values and Python UTF-8 defaults.

Native shell and executable jobs explicitly supply bounded `SystemDrive`, `ProgramFiles`, `ProgramFiles(x86)` and `ProgramData` defaults from the Windows host. Case-insensitive explicit caller overrides remain authoritative; absent or oversized defaults are omitted. `SystemDrive` supports Windows/.NET known-folder resolution used by MSBuild; arbitrary host environment variables remain excluded.

For a complete build or verification command, use `process_launch` with the actual executable in `command`, exact `args`, `cwd`, explicit `env`, and `timeout_sec`. Keep the returned `job_id`, PID, receipt, and stdout/stderr paths. Poll `process_poll` every five seconds or longer, or use `process_wait` for up to 30 seconds per call. Waiting timeout leaves the owned job running. Use `process_read_log` with `stream` and either `tail_lines` or byte `offset`, then follow `next_offset` while `has_more` is true. Inspect actual terminal state and exit status before reporting success.

For an already initialized CMake build tree, use `cmake_test_run` with explicit `build_dir`, optional `config`/CTest `filter`, and default `mode: "test"`. Explicit `mode: "build_and_test"` first builds, with optional build `target`, and starts CTest only after actual confirmed build success. Its `timeout_sec` is one shared 1–3,600-second budget (default 1,800), not a fresh timeout per phase. Read `cmake_test_status` for actual build/test results and nullable validated JUnit counts; outer `ok` only describes retrieval. Failure pages use `failure_offset` and `max_failures` 1–32, with UTF-8 excerpts and a 24 KiB encoded row-list bound. Missing, interrupted or invalid reports do not invent counts or expected/actual assertion values. Use the returned job ID with the existing log/wait/kill tools. See [CMake/CTest examples, report seals and crash recovery](CMAKE-CTEST.md); these tools do not configure a tree implicitly or add clangd.

When the persistent Manager is available, it owns brokered jobs across MCP reconnects. Use `process_list` to recover jobs and `process_adopt` to verify a retained Forge receipt and process identity after reconnecting; arbitrary PIDs cannot be adopted. `process_kill` requests cancellation, so confirm the terminal state afterward. An interrupted broker reports unknown exit status rather than successful completion. Standalone jobs remain connector-owned. The service bounds are two active jobs, sixteen results retained in memory, thirty-two durable jobs per project, and a 3,600-second maximum lifetime; shutting down the owner cancels active work.

`shell_job_start`, `shell_job_status`, `shell_job_list`, and `shell_job_cancel` provide the corresponding foreground PowerShell convenience route. The status envelope's top-level `ok` describes retrieval. Require `done`, terminal `state`, the nested command result, actual exit code, and timeout/cancellation/termination/truncation flags. Preserve the task's original full command and report contract. A detached child inside `shell_exec` cannot extend that call's process-tree lifetime.

Use `provider_status` for observed loaded LM Studio model/context information and `process_status` for native process/service facts. Missing provider file/revision/version facts retain their unknown state and provenance. `github_read` supports fixed read-only repository/run/artifact/ref/pull-request routes and returns credential, permission, or network failures explicitly.

For an external evidence directory, inspect `workspace_authority` in `get_forge_status`. Owner-selected `filesystem_access: host` uses available ordinary local-volume roots with native ACL/path checks. In `workspace` mode, the owner must already configure the exact existing external directory in `allowed_roots`; call `workspace_authority_bind` to activate it for the project. Activation remains available after continuity narrows the workspace, and subsequent recovery keeps explicitly bound additional roots. A model cannot approve a new root, change filesystem mode or restore removed permissions. In workspace mode, bind the configured directory again after a connector/Manager restart. `fs_*`, `shell_exec`, `shell_job_start`, and `process_launch` use the active authority, with process working directories checked before Manager dispatch. Status reports active roots and cwd policy.

Working-directory validation does not sandbox an arbitrary shell or executable's absolute path arguments or later directory changes. Shell-enabled commands run with the user's operating-system permissions. Filesystem tools continue to enforce their path authority. Existing `fs_write` covers the requested 64 KiB file-write route below active authorized roots while retaining Windows path checks. Its file-layer cap is 2 MiB, but the complete encoded MCP request must fit the smaller 1 MiB transport/document limit, including JSON escaping and other fields. Native-tool directory/file open and creation failures, and atomic `fs_write` replacement failures, use `filesystem_access_denied` for Win32 access denials and identify the path, operation, and native code. Authority-policy denials retain `unauthorized` or `path_outside_authority`; inspect the error’s operation and diagnostic text as well as its code.

Call `evidence_digest` with one to 64 authorized file paths for streamed binary SHA-256 and byte lengths. Save the capture identity and returned head digest outside the capture log. `evidence_log_read` verifies the full persisted chain by default and pages records with `offset` and `limit` (one to sixteen). The chain is unkeyed; an independently retained head is required to detect replacing and rehashing every record. Capture limits are 32 KiB aggregate path text, 64 GiB per file, 128 GiB total, and an 8 MiB log. Invalid or full logs fail without replacing existing evidence.

`verification_env_create` starts an owned Python venv job below a bound additional root, outside the main source root. Supply the real `python_path`, a new destination `path`, and supported pins `jsonschema==4.25.1` and `PyYAML==6.0.3`. It refuses an existing destination and uses binary wheels. Require successful job completion, then call `verification_env_status` for `verification-env.json` and the observed runtime/distribution versions. The venv isolates dependency writes; it is not an operating-system sandbox and does not enforce read-only behavior for arbitrary subsequent commands.

For a task that authorizes independent review, call `reviewer_start` with exactly one of an authorized `opening_message_path` or an inline `opening_message`, plus the review `authorization` reference and task text. Both opening sources are bounded to 65,536 UTF-8 bytes and reject NUL or invalid UTF-8. File paths must remain under an active authorized root; bind an owner-configured evidence root before reading its opening file. Inline input avoids copying a message file into the source repository.

`receive_timeout_sec` sets each provider Responses request's receive budget from 1 to 3,600 seconds, defaulting to 600. It is separate from LM Studio's 180-second outer MCP-call deadline: `reviewer_start` returns the owned run identity, and inference continues while you poll status. It is also separate from a total reviewer lifetime; each provider turn observes its own receive budget from request submission through response-body completion. The asynchronous reviewer continues independently of the admitting MCP request; direct transport calls also observe their operation context's remaining hard deadline. Model discovery and remote cancellation retain their separate request bounds. Cancellation remains available while receiving a response. Default `mode: "tools"` starts a fresh Manager-owned provider context without executor history and constrains reviewer tools to reads. Optional `mode: "text_only"` omits tools and explicitly limits review to supplied text; external evidence remains unverified.

Inspect `reviewer_status` for state, output, provider usage, chosen `receive_timeout_sec`, `mode`, `failure_category`, and `infrastructure_blocked`. A transport deadline is infrastructure failure, not a reviewer verdict. Use `reviewer_cancel` when needed. A failed/cancelled run or executor self-review does not approve an independent gate. The caller's authorization reference is recorded context rather than proof of a human grant; apply the task's real authorization and verdict requirements. Dedicated reviewer receipts preserve the full task, chosen timeout, and report with SHA-256 verification. Historical receipts without a chosen timeout return null for that field. A report is capped at 256 KiB and exposes `output_truncated`; up to sixteen reviewers may run simultaneously. Completed receipts remain available by run ID and do not consume lifetime admission capacity. Retained files need disk space. An interrupted receipt is marked failed with unknown outcome and retained pending calls, which are never replayed.

## Auto Continuity and packets

The Workspace/dashboard **Auto Continuity** toggle is persisted for the selected project/provider. Settings exposes effective capacity, next-response reserve, handoff reserve, and safety margin.

Inspect `get_forge_status.context_telemetry` for the latest completed provider generation's usage, capacity, reserves, headroom, source, generation reference, and observation time. Messages added after that generation are not measured; missing observations stay unavailable/null. `auto_continuity.readback_confirmed` confirms this MCP client retrieved the current packet through `context_get`. A completed job's `memory_attached` is a separate persistence outcome and must be checked when the task requires a memory receipt.

The primary worker reads the selected native LM Studio conversation's actual generation usage and loaded capacity. At context reserve pressure it stops generation at a completed tool boundary without cutting off an active Forge tool. It requests a detailed model-written packet containing goal, verified work, decisions and constraints, files, blockers, agent sessions, and ordered next actions. `session_handoff` saves that packet and publishes project-scoped pickup.

The product opens **New chat** through Windows UI Automation, retains the same three integrations and loaded model, sends the packet, and checks the exact successor conversation ID and persisted handed message. The successor calls `context_get` and then another Forge tool. Packet storage or an MCP connection ID alone is not credited as native chat rollover.

Auto Continuity was verified with a reserve-triggered pause, not physical context exhaustion. Rollover was verified while the primary MCP worker stayed alive. Interrupted handoff after idle-process eviction is not durable and is not claimed.

The **Continuity** view shows saved packets and selected packet detail. Use **Refresh packets**, **Delete selected packet**, or **Clear all packets**. These actions remove saved records, not policy folders or project source files.

## Memory and Settings

Workspace **Search** reads a bounded page. **Display All** follows Manager cursors in 100-record pages and rejects inconsistent counts, repeated cursors, or changed record sets. Select a record to inspect or edit it.

Settings retains **Load effective settings**, **Save and read back**, **Revert pending edits**, **Test LM Studio**, and **Restart Manager**. Under **Saved project records**, select one or more records and press **Delete selected**, or use a row's **Delete record**. **Refresh records** reloads authoritative state. Source folders are not deleted. The old scope-reset scheme and Apply and Verify are removed.

Rig's **Runtime configuration** card provides **Ensure manager**, **Restart service** and **Stop service**, using the existing Manager actions. Finish owned work or confirm terminal cancellation before restarting or stopping Manager. Scheduled triggers require Manager to remain running. These controls are present in the 1.3.19 App source; installed UI acceptance is recorded separately after execution.

Managed Run, its readback, Export selected project, Import verify first, the Actions frame and Invoke Tool, Advanced Canonical Catalog, Scope Test, and Reset Scope are removed. `agent_run_start`, `agent_run_status`, and `agent_run_complete` remain baseline specialist-session tools.

Version 1.3.6 keeps Rig layout stable during background telemetry refresh without disabling updates. Rig shows unavailable or stale observations explicitly. Activity displays operational and governance outcomes. Ordinary data lives at `%LOCALAPPDATA%\Forge Conductor`; disposable validation uses a separate home.
