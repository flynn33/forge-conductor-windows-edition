## Implementation starting points
Current production composition owns `UnavailableTelemetryService`. Its `sample()` returns unavailable. Implement real Windows collectors behind existing `ITelemetryService`/domain telemetry contracts, then compose them in the Manager. This is missing functionality, not an optional cosmetic enhancement. Inspect the existing dashboard telemetry/events projection before adding a parallel transport.

Collect system CPU deltas, physical memory and Forge process resources with supported native APIs. Associate process identity with a stable creation/instance identity, not a stale PID alone. Attempt supported GPU adapter/usage/memory collection through Windows-supported interfaces already appropriate to this stack; classify unsupported measurements honestly. Do not require a vendor driver SDK or pretend dedicated VRAM equals total system RAM. Unsupported GPU capability cannot excuse leaving CPU/RAM absent.

Publish timestamped, scoped typed snapshots; share response/context/run state with R1 rather than summing estimates differently in the GUI. Bound histories in memory and coalesce UI updates. A collector failure must not crash an ordinary run; loss of the provider must not erase valid host metrics. Preserve metadata for warming up, measured, estimated, stale, unavailable and error states.

Create reusable native chart/gauge/status/timeline components and feature view models, not a giant MainWindow switch. Rig must display actual resource histories and operational health, with Provider/Continuity/Runtimes/Projects/Events drill-down. Keep raw JSON as optional evidence, not the primary display. See the metric/semantics table in TELEMETRY-AND-UI: ordinary current transport is non-streaming, so TTFT or decode tokens/sec cannot be fabricated from whole-request latency.

Run the real collector/GUI once, compare reasonable scoped values to a matching Windows observation and inspect reconnect/stale/history reset. Add a few regression cases for delta calculation, invalid/unavailable samples and lifecycle release. Keyboard/text equivalents/high contrast and one scaled layout are sufficient; no new golden-image or performance campaign. Integrating missing R1 operational fields remains an explicit dependency, not a static demonstration substitute.
